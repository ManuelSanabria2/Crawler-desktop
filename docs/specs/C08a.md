## Objetivo

Que GEASS pueda ejecutar una orden de Manuel sobre la interfaz de una app: abrir una app, el explorador o una tecla multimedia (acciones directas de C07), o actuar sobre un elemento de una ventana (pulsar, alternar, desplegar, contraer o seleccionar). La orden se resuelve en el orden de la sección 6.9: acción directa, elemento en la ventana actual por su patrón de UI Automation, ruta del grafo, detector visual (solo la interfaz) y clic por coordenadas como último recurso. Después de cada acción se comprueba que pasó lo esperado; si no, se reintenta una vez y luego se reporta el fallo.

Toda acción pasa antes por una puerta de seguridad que la clasifica como libre, que requiere confirmación o prohibida, según las listas de `safety.yaml`. La confirmación es un callback; hay uno de CLI y otro que siempre niega. Los botones de autorización solo se pulsan con una orden explícita para esa acción, en una ventana permitida y con confirmación. Cada intento, hecho o rechazado, queda en la auditoría.

Es el código más delicado del crawler: actúa en el escritorio real de Manuel por orden suya. Por eso lo que toca el sistema sigue en `system.py`, todo lo que actúa pasa por un único método del ejecutor que exige una autorización de la puerta, y ante la duda no se hace nada.

### request.py

```python
RequestKind = Literal["launch", "explorer", "media", "element"]
RequestAction = Literal["invoke", "toggle", "expand", "collapse", "select", "coordinate_click"]


class ElementExpectation(BaseModel):
    """Un elemento que debe estar presente. Se compara con todos los criterios dados."""

    name: str = ""  # nombre; se compara normalizado y exacto
    automation_id: str = ""  # exacto
    control_type: str = ""  # exacto


class Expectation(BaseModel):
    """Lo que debe verse después de la acción. Todas las condiciones dadas a la vez."""

    process: str = ""  # ejecutable de la ventana
    title: str = ""  # expresión regular, con re.search e IGNORECASE
    window_class: str = ""  # clase de la ventana, exacta
    new_window: bool = False  # las condiciones se buscan en una ventana que no estaba antes
    element: ElementExpectation | None = None


class ActionRequest(BaseModel):
    """Una orden para el ejecutor."""

    kind: RequestKind
    app: str = ""  # launch: nombre aproximado de la app; element: ejecutable, p. ej. "notepad.exe"
    path: str | None = None  # explorer: carpeta, opcional
    media: MediaAction | None = None  # media: la acción multimedia
    name: str = ""  # element: nombre del elemento
    automation_id: str = ""  # element: AutomationId
    control_type: str = ""  # element: tipo de control, opcional
    action: RequestAction | None = None  # element: None = según los patrones del elemento
    authorize: bool = False  # element: orden explícita de pulsar un botón de autorización
    expect: Expectation | None = None

    def describe(self) -> str:
        """Texto legible de la orden."""
```

Validación (con `model_validator(mode="after")`; un fallo es `ValidationError`):

- `ElementExpectation`: al menos uno de `name` o `automation_id` no vacío tras `strip()`.
- `Expectation`: al menos una condición (`process`, `title`, `window_class`, `new_window` verdadero o `element`). `title` debe compilar como expresión regular.
- `ActionRequest`, según `kind`:
  - `launch`: `app` no vacío; `path`, `media`, `action` en `None`; `name`, `automation_id`, `control_type` vacíos; `authorize` falso.
  - `explorer`: `app`, `name`, `automation_id`, `control_type` vacíos; `media` y `action` en `None`; `authorize` falso. `path` opcional.
  - `media`: `media` obligatorio; el resto vacío o `None`; `authorize` falso; `expect` debe ser `None` (una tecla multimedia no tiene nada que comprobar en pantalla).
  - `element`: `app` termina en `.exe` (sin distinguir mayúsculas); al menos uno de `name` o `automation_id` no vacío; `path` y `media` en `None`.
- `describe()`:
  - `launch`: `Abrir "{app}"`.
  - `explorer`: `Abrir el explorador` o `Abrir el explorador en {path}`.
  - `media`: `Tecla multimedia {media}`.
  - `element`: `{verbo} "{name}" ({control_type}) en {app}`. Si `name` está vacío va `[{automation_id}]` sin comillas; sin `control_type` se omite el paréntesis. Verbos: `invoke` Pulsar, `toggle` Alternar, `expand` Desplegar, `collapse` Contraer, `select` Seleccionar, `coordinate_click` Hacer clic en, `None` Usar.

    process_id: int
    process_name: str  # p. ej. "Notepad.exe"; vacío si no se pudo leer

class LiveElement:
    """Un elemento vivo de la interfaz. ``ref`` es el elemento COM; fuera de desktop_win es opaco."""

    props: NodeProps
    process_id: int
    window_handle: int  # ventana de nivel superior en la que se encontró
    ref: Any = field(default=None, compare=False, repr=False)


@dataclass(frozen=True)
class VisualQuery:
    name: str
    automation_id: str
    control_type: str


@dataclass(frozen=True)
class VisualCandidate:
    rect: Rect  # coordenadas de pantalla
    label: str  # clase del detector, p. ej. "button"
    score: float  # 0 a 1


class VisualDetector(Protocol):
    """Detector visual de elementos (sección 6.11). En esta versión no hay ninguno real."""

    def locate(self, window: WindowRef, query: VisualQuery) -> list[VisualCandidate]: ...


class Desktop(Protocol):
    """Lo que el ejecutor necesita del escritorio. El real es ``WinDesktop``."""

    def foreground(self) -> WindowRef | None: ...
    def windows(self) -> list[WindowRef]: ...
    def find(
        self, window: WindowRef, *, name: str = "", automation_id: str = "", control_type: str = ""
    ) -> list[LiveElement]: ...
    def element_at(self, x: int, y: int) -> LiveElement | None: ...
    def state(self, element: LiveElement) -> PatternState: ...
    def snapshot(self, window: WindowRef) -> WindowDump: ...
    def perform(self, element: LiveElement, op: PatternOp) -> None: ...
    def click(self, x: int, y: int) -> None: ...
    def close(self, window: WindowRef) -> None: ...


def element_label(props: NodeProps) -> str:
    """El nombre, o [AutomationId], o [sin nombre]."""
```

Contrato de `Desktop` (lo cumplen `WinDesktop` y el doble de los tests):

- `foreground`: la ventana en primer plano, o `None` si no se puede determinar.
- `windows`: ventanas de nivel superior visibles, no ocultas por DWM (`DWMWA_CLOAKED`) y con título, como `visible_windows` de `tests/crawler/conftest.py`.
- `find`: busca en `window` y en las demás ventanas de nivel superior visibles del mismo proceso (con o sin título: así entran los menús emergentes). Devuelve los elementos que cumplen todos los criterios dados: `automation_id` exacto, nombre normalizado igual al `name` normalizado, `control_type` exacto. Con los tres vacíos: `ValueError`. Orden: primero `window`, después las demás por handle; dentro de cada una, en orden de recorrido.
- `element_at`: el elemento bajo un punto de la pantalla, o `None` si no hay o si su proceso está en `apps.excluded`.
- `state`: el estado de los patrones que tiene el elemento (`None` en los que no tiene).
- `snapshot`: el volcado de la ventana, con `dump_window`.
- Las lecturas lanzan `ExcludedAppError` si la ventana es de una app excluida, y `UiaError` si falla UI Automation. Nunca leen valores de texto.
- `perform`, `click` y `close` son las únicas que actúan. Lanzan `ActionError` si fallan.

    "invoke": ("Invoke", "Invoke"),

def perform_pattern(element: Any, op: str) -> None:
    """Aplica un patrón de UI Automation a un elemento vivo: invocar, alternar, desplegar, contraer o seleccionar."""


def click_at(x: int, y: int) -> None:
    """Clic izquierdo en un punto de la pantalla (píxeles físicos), con SendInput."""


def close_window(handle: int) -> None:
    """Pide a una ventana que se cierre con WM_CLOSE. Nunca a la barra de tareas ni al escritorio."""

- `perform_pattern`: `op` fuera de `PATTERN_OPS` o `element` en `None`: `ActionError` sin tocar nada. Obtiene la interfaz con `get_elem_interface(element, patrón)` (importado dentro de la función); `NoPatternInterfaceError` se convierte en `ActionError("El elemento no admite ...")`. Llama al método de la tabla, sin argumentos. `COMError` u `OSError`: `ActionError`. Es la lista cerrada de operaciones: no hay ninguna otra, y en particular nada de `ValuePattern`, `SetValue` ni `LegacyIAccessible`.
- `click_at`:
  1. `x` e `y` deben ser `int` exactamente (no `bool`, no `float`); si no, `ActionError`.
  2. Pide al proceso conciencia de DPI por monitor (`SetProcessDpiAwarenessContext` con `-4`); si falla, sigue (ya puede estar fijada).
  3. Lee el escritorio virtual con `GetSystemMetrics` (76, 77, 78 y 79). Un punto fuera: `ActionError`.
  4. Mueve el cursor con un `SendInput` de un evento de mouse con `MOUSEEVENTF_MOVE | MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` y coordenadas normalizadas `round((x - left) * 65535 / (width - 1))` (igual para `y`).
  5. Lee el cursor con `GetCursorPos`. Si no está a 1 píxel o menos de `(x, y)` en cada eje: `ActionError` y no hace clic.
  6. Envía en un solo `SendInput` dos eventos: `MOUSEEVENTF_LEFTDOWN` y `MOUSEEVENTF_LEFTUP`. Si `SendInput` devuelve menos eventos de los enviados: `ActionError`.
  - La estructura `_PointerInputLayout` pasa a ser `_MouseInput` y se usa; su comentario se actualiza. Las constantes de Win32 van con nombre y comentario.
  - Solo botón izquierdo, un clic. No hay doble clic, ni arrastre, ni botón derecho, ni rueda.
- `close_window`: `handle` debe ser `int` mayor que 0; `win32gui.IsWindow` falso: `ActionError`; clase de la ventana en `SHELL_WINDOW_CLASSES`: `ActionError`. Envía `win32gui.PostMessage(handle, WM_CLOSE, 0, 0)` (0x0010). Un error de pywin32: `ActionError`. `win32gui` se importa dentro de la función.
- La docstring del módulo y la de `MEDIA_KEYS` se actualizan: `SendInput` envía solo las seis teclas multimedia y el clic izquierdo de `click_at`.

- `split_identifier`: inserta un espacio entre minúscula o dígito y mayúscula, y entre letra y dígito (en los dos sentidos); cambia `_`, `-` y `.` por espacios.
- `check_app(executable)`: `forbidden` con regla `excluded_app` si es igual a un ejecutable de `apps.excluded`; `forbidden` con `never_automate` si está en algún grupo de `NEVER_AUTOMATE_PROCESSES` de los listados en `never_automate`. Si no, `None`.

  2. `op` es `set_value` o `unknown`: `forbidden`, `unsupported_action` ("el ejecutor no escribe texto ni hace acciones desconocidas").

     - Coincidencia por subcadena: el patrón aparece dentro del texto.
     - Coincidencia por palabra: se cambia todo lo que no sea letra o dígito por espacios, se parte en palabras, y la secuencia de palabras del patrón aparece seguida en la del texto.

  5. Botón de autorización (`authorization.button_patterns` coincide con el nombre o el identificador):
     - si no se cumple `is_target and authorize`: `forbidden`, `authorization`, con la razón "Botón de autorización: solo se pulsa con una orden explícita y actual tuya para esta acción concreta.";
     - si se cumple: se lee `safety.crawler.authorization.allowed_windows`. Si sigue como `TODO`, la `ConfigIncompleteError` se deja pasar sin capturarla. Si alguna entrada tiene `executable` igual al de la ventana y su `title_pattern` coincide con `re.search(..., window.title, re.IGNORECASE)`: `confirm`, `authorization`. Si ninguna: `forbidden`, `authorization_not_allowed`.
  6. `blocklist_patterns`: `confirm`, `blocklist_patterns`.
  7. `confirmation_dialog_accept_patterns`: `confirm`, `confirmation_dialog_accept_patterns`.
  8. `require_confirmation_patterns`: `confirm`, `require_confirmation_patterns`.
  9. Nombre e identificador vacíos los dos: `confirm`, `unnamed` ("elemento sin nombre: no se puede comprobar con las listas de safety.yaml").
  10. `free`, `free`.

    def __init__(self, who: str = "nadie") -> None: ...

    def requests(self) -> list[ConfirmationRequest]: ...

    def __call__(self, request: ConfirmationRequest) -> bool: ...  # anota y devuelve False
```

- `CliConfirmer.__call__` escribe, con `write`, una línea por dato:
  - `Esta acción necesita tu confirmación:`
  - `  Acción: {description}`
  - `  Motivo: {reason}`
  - `  Regla: {rule}` y, si hay patrón, ` (patrón '{pattern}')` en la misma línea.
  - Si `is_target` es falso: `  Es un paso intermedio de la ruta hasta el objetivo.`
  - Si `rule` es `authorization`: `  Es un botón de autorización. Solo se pulsa si lo confirmas ahora.`
  - Después llama a `read("¿Lo hago? [s/N]: ")`. Devuelve verdadero solo si la respuesta, con `strip().casefold()`, es `s`, `si`, `sí`, `y` o `yes`. Cualquier otra respuesta, cadena vacía, `EOFError` o `KeyboardInterrupt`: falso.
- Una respuesta vale para esa acción concreta y nada más: el ejecutor pregunta otra vez en cada acción que lo requiera.

`__init__`: `authorized_by` vacío: `ValueError`. Crea `SafetyGate(safety, config)` y `SignatureRules.from_config(config.signature)`.

`from_config`: carga `crawler.yaml` y `safety.yaml`; `WinDesktop(config)`; `AuditLog.from_config(safety)`; `AppIndex.load(config, safety)`; el grafo con `CrawlerGraph.from_store(store, config)`, abriendo `CrawlerStore.from_config(config)` como gestor de contexto y cerrándolo al terminar, solo si el archivo de `store.db_path` (resuelto con `resolve_project_path`) ya existe; si no, `None`. No crea la base. Sin detector.

#### Reglas generales de `run`

- Antes de cada intento que actúe, si `should_stop()` es verdadero: estado `aborted` ("Parada pedida.").
- Toda llamada a `desktop.perform` o `desktop.click` está en un único método privado, `_perform`, que recibe una autorización de la puerta (un objeto privado `_Clearance`, creado solo por el método que consulta la puerta y, si hace falta, al confirmador) y comprueba que corresponde al mismo elemento (`process_id`, `window_handle` y `props`) y a la misma operación. Ningún otro método del ejecutor llama a `perform` ni a `click`. `desktop.close` no se llama nunca desde el ejecutor.
- Simulación (`dry_run`): resuelve y consulta la puerta igual, pero no llama al confirmador, ni a `perform`, `click`, `launch` (salvo con `dry_run=True`), `open_explorer` ni `media`. Si se habría hecho algo, el estado es `would_do`, con la decisión de la puerta en el intento ("libre" o "requeriría confirmación"). Si la puerta prohíbe, `forbidden`. Una simulación no se audita.
- Auditoría, sin simulación:
  - Una línea por intento de acción sobre la interfaz, hecho o rechazado: `action="ui:{op}"`, `target=element_label(props)`, `app` = ejecutable de la ventana, `result` = el del intento, `authorized_by` = el del ejecutor, y `details` con `strategy`, `step`, `try`, `control_type`, `automation_id`, `gate_verdict`, `gate_rule`, `pattern`, `confirmed_by` (el `who` del confirmador si confirmó; si no, `None`) y `verified`.
  - Una línea final por llamada a `run`: `action="execute"`, `target=request.describe()`, `app` (el `app` de la orden; `explorer.exe` para el explorador; vacío para multimedia), `result` = el estado final, y `details` con `strategy`, `attempts` (número), `performed` (número) y `message`.
  - Si `run` termina por una excepción (por ejemplo `ConfigIncompleteError`), se escribe la línea final con `result="error: {mensaje}"` y después la excepción se vuelve a lanzar.
- Reintentos: si la verificación falla, se repite la misma acción hasta `executor.max_retries` veces más, volviendo a buscar el elemento vivo y a consultar la puerta. Una acción que necesitó confirmación no se reintenta nunca: se reporta `failed`. Si la puerta cambia de decisión en el reintento, manda la nueva.
- Si `executor.verify_transition` es falso, no se verifica: la acción hecha queda `done_unverified` y no hay reintentos.
- Una `ActionError` de `perform`, `click` o de una acción directa: intento con `error: {mensaje}`, sin reintento, estado `failed`.

#### Orden de resolución

Se recorren los pasos de `executor.resolution_order` en su orden, saltando los que no aplican al tipo de orden.

- Órdenes `launch`, `explorer` y `media`: solo aplica `direct_action`. Si no está en `resolution_order`: `forbidden` ("direct_action no está en executor.resolution_order").
- Órdenes `element`: aplican `current_window_element`, `graph_route`, `visual_detector` y `coordinate_click`, en el orden de la lista. Una estrategia que hace algo, o que llega a un estado `ambiguous`, `denied`, `forbidden`, `aborted` o `would_do`, termina la resolución. Una que no encuentra el objetivo deja pasar a la siguiente.
- Si ninguna actuó: `failed` si alguna encontró el elemento pero no pudo actuar (con el motivo; por ejemplo, "se encontró, pero no admite toggle"); si no, `not_found`.

#### Acción directa (`direct_action`)

- `launch`: llama a `launcher.launch(request.app, authorized_by=..., index=..., config=..., safety=..., audit=..., dry_run=self.dry_run)`. Estados: `ambiguous`, `not_found` y `blocked` pasan tal cual, sin reintento; `would_do` si es simulación.
  - Antes de lanzar se toma `capture_baseline` de la ventana en primer plano (o un `Baseline` con solo `window_handles` si no hay).
  - Con `launched`, verifica durante `executor.launch_timeout_s`:
    - con `request.expect`: `expectation_met`;
    - sin ella: hay una ventana nueva (handle que no estaba en el `Baseline`), o la ventana en primer plano, que no es de una app de `apps.excluded` y cuyo título cumple `rapidfuzz.fuzz.partial_ratio(normalize_text(nombre_de_la_app), normalize_text(título)) >= launcher.fuzzy_match_threshold`, donde `nombre_de_la_app` es `result.entry.name`.
  - Si se agota el tiempo sin verificar y sin `expect`, pero apareció una ventana nueva de una app de `apps.excluded`: `done_unverified` (su título no se lee), sin reintento. Las ventanas que ya estaban no cuentan para esto.
  - Si no se verifica, se lanza otra vez (hasta `max_retries`) y se vuelve a esperar. Si sigue sin verificarse: `failed`.
- `explorer`: comprueba que `open_explorer` está en `launcher.direct_actions` (si no, `forbidden`), llama a `direct.open_explorer(request.path, authorized_by=..., config=..., audit=...)` y verifica durante `executor.launch_timeout_s`: con `expect`, `expectation_met`; sin ella, hay una ventana nueva de `explorer.exe` con clase `CabinetWClass`. Reintento igual que `launch`. `ActionDisabledError`: `forbidden`. Otra `ActionError`: `failed`.
- `media`: llama a `direct.media(...)`. Resultado `done_unverified`, sin verificación ni reintento. `ActionDisabledError`: `forbidden`.
- El ejecutor no escribe líneas `ui:` para las acciones directas: ya las audita C07. Sí escribe la línea final `execute`.

#### Antes de cualquier estrategia de elementos

1. `gate.check_app(request.app)`: si prohíbe, `forbidden` sin leer nada del escritorio (ni `foreground`).
2. `window = desktop.foreground()`. Si `gate.check_window(window)` prohíbe, `forbidden`. Si el ejecutable de `window` no es igual a `request.app`: `aborted` ("La ventana en primer plano no es de {app}: no actúo sobre ventanas que no puedo confirmar."). No se trae ninguna ventana al frente.

#### Elemento en la ventana actual (`current_window_element`)

1. `candidatos = desktop.find(window, name=request.name, automation_id=request.automation_id, control_type=request.control_type)`.
2. Se quedan los habilitados. Si hay más de uno, se prefieren los que no están fuera de pantalla (`offscreen` falso). Si siguen siendo más de uno: `ambiguous`, sin actuar, con hasta 5 candidatos en el mensaje (etiqueta y tipo). Si no hay ninguno habilitado pero sí deshabilitados: se anota "está deshabilitado" y se pasa a la siguiente estrategia. Si no hay ninguno: siguiente estrategia.
3. Operación:
   - Si `request.action` es `coordinate_click`: el elemento se guarda para `coordinate_click` y se pasa a la siguiente estrategia.
   - Si `request.action` es otra: debe estar su patrón en `props.patterns` (`invoke` Invoke, `toggle` Toggle, `expand` y `collapse` ExpandCollapse, `select` SelectionItem). Si no: se anota "no admite {acción}", se guarda el elemento para `coordinate_click` y se pasa a la siguiente.
   - Sin `request.action`: `infer_action("left", props.patterns)`. `expand_collapse` se convierte en `collapse` si `desktop.state(elemento).expand` es `expanded`, y en `expand` en cualquier otro caso. `coordinate_click` significa que no tiene patrones de acción: se guarda el elemento y se pasa a la siguiente.
4. Se actúa (ver "Un intento") con `is_target=True` y `request.authorize`.

#### Ruta del grafo (`graph_route`)

1. Sin grafo: no aplica. La app del grafo es la de ejecutable igual a `request.app` entre `graph.apps()`; si no hay, no aplica.
2. Estado actual: `compute_signature(desktop.snapshot(window), reglas).structural` comparada con `structural_signature` de los estados de esa app (`graph.states_of`). Sin coincidencia: no aplica ("no conozco el estado actual").
3. Objetivos: elementos de los estados de esa app (`graph.elements_of`) con `automation_id` igual (si la orden lo da), nombre normalizado igual (si lo da) y `control_type` igual (si lo da). Sin coincidencia: no aplica. No se usa la búsqueda difusa del grafo.
4. Para cada objetivo, `graph.path_to(app.executable, estado_actual.id, elemento.id)`; los `NoRouteError` se saltan. Se elige la ruta de menor `cost`; a igual coste, la del objetivo de menor id. Sin rutas: no aplica. Si la ruta solo tiene el paso final, no aplica ("el objetivo está en la vista actual, pero no se encontró en la ventana").
5. Cada paso intermedio `n` (1, 2, ...) se hace así:
   - se lee otra vez la ventana en primer plano y se aplica la comprobación de "Antes de cualquier estrategia" (si falla, `aborted` o `forbidden`);
   - se busca el elemento vivo con `desktop.find` por el `automation_id` del registro si no está vacío, o si no por su nombre, y además por su `control_type`; debe quedar exactamente uno habilitado; si no, `failed` ("la ruta se rompió en el paso {n}: ...");
   - operación según `step.action_type`: `invoke`, `toggle` y `select` tal cual; `expand_collapse` según el estado, como arriba; `coordinate_click` solo si `coordinate_click` está en `resolution_order`, y con el procedimiento de esa estrategia; si no, `failed`;
   - se actúa con `is_target=False` (un botón de autorización en un paso intermedio siempre está prohibido);
   - verificación: la firma estructural del volcado de la ventana en primer plano es igual a la `structural_signature` del estado `step.expected_state_id`, y su ejecutable es igual a `request.app`.
   - Si el paso no queda `done`, la resolución termina con ese estado.
6. Paso final: se aplica `current_window_element` sobre la ventana en primer plano de ese momento. Si allí no se encuentra el objetivo: `failed` ("la ruta llegó, pero el objetivo no está en la ventana").

#### Detector visual (`visual_detector`)

- Sin detector: no aplica (se anota "no hay detector visual").
- Con detector: `detector.locate(window, VisualQuery(...))`. Se toma el candidato de mayor `score` que llegue a `vision.score_threshold`; si no hay, no aplica.
- Su centro (división entera) se confirma con `desktop.element_at(x, y)`: tiene que existir, ser del mismo `process_id` que la ventana, y su nombre normalizado y su `automation_id` tienen que ser iguales a los de la orden (los que la orden dé). Si no, no aplica ("el detector no coincide con lo que hay en pantalla").
- Si se confirma, se actúa con un clic en ese punto, como en `coordinate_click`, con la puerta sobre las propiedades del elemento leído en el punto.

#### Clic por coordenadas (`coordinate_click`)

- Solo sobre un elemento vivo guardado por `current_window_element` (o por el paso final de una ruta). Nunca con un rectángulo guardado en la base ni con coordenadas que vengan de fuera.
- Requisitos: `rect` no es `None`, `offscreen` es falso y el elemento está habilitado. El punto es el centro del rectángulo (división entera) y debe estar dentro del rectángulo de la ventana (si la ventana tiene `rect`).
- `desktop.element_at(x, y)` debe devolver un elemento del mismo `process_id` con el mismo `control_type`, nombre y `automation_id`. Si no (otro elemento lo tapa, o no hay nada): no se hace clic; se anota "otro elemento tapa el objetivo" y el resultado final es `failed`.
- La puerta se consulta con `op="coordinate_click"`.
- Verificación: con `request.expect`, `expectation_met`; sin ella, la verificación por defecto de `invoke`.

#### Un intento (consulta a la puerta, acción y verificación)

1. `decision = gate.check(props=..., op=..., window=..., is_target=..., authorize=...)`.
2. `forbidden`: intento con `forbidden: {regla}`; estado `forbidden`.
3. `confirm`: en simulación, `would_do`. Si no, se llama al confirmador con un `ConfirmationRequest`; si devuelve falso: intento `denied` y estado `denied`.
4. Simulación: `would_do`.
5. `baseline = capture_baseline(desktop, window, elemento)`.
6. Se vuelve a leer `desktop.foreground()`; si su handle no es el de `window`: `aborted`, sin actuar.
7. `_perform`.
8. Verificación, con `wait_until` durante `executor.verify_timeout_s` y pausa `verify_poll_s`:
   - con `request.expect` (solo en la acción final): `expectation_met`;
   - paso intermedio de ruta: la firma del estado esperado, como se dijo;
   - por defecto, según la operación: `toggle`, el estado `toggle` es distinto del de `baseline`; `expand`, `expand == "expanded"`; `collapse`, `expand == "collapsed"`; `select`, `selected is True`; `invoke` y `coordinate_click`, "cambió algo": el handle en primer plano es otro, o el conjunto `process_handles` es otro, o el handle de `window` ya no está en `desktop.windows()`, o `ui_fingerprint(desktop.snapshot(window))` es distinto de `baseline.fingerprint`.
9. Verificado: `done`. No verificado: reintento según las reglas generales; si se agotan, `failed`.
